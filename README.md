# Эктоконтроль для Home Assistant

Неофициальная пользовательская интеграция личного кабинета Эктоконтроля. Подключает адаптер котла, программы и оборудование к Home Assistant через облако производителя.

## Возможности

- Данные адаптера котла и доступные настройки отопления и ГВС.
- Автоматическое обнаружение новых программ и оборудования при опросе каждые 60 секунд.
- Поддерживаемые параметры программ отопления, охраны, уведомлений, реакции на датчики и расписания.
- Датчики и управление поддерживаемыми выходами, с учётом блокировки управления в кабинете.
- Повторная авторизация при потере доступа.

Поддержка зависит от типа объекта и полей, возвращаемых кабинетом. Не все поля, виджеты или виды оборудования имеют управление. Интеграция не является редактором полного расписания или всех правил программы.

## Установка вручную

1. Скопируйте папку `custom_components/ectocontrol_boiler` в `/config/custom_components/` Home Assistant.
2. Перезапустите Home Assistant.
3. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Эктоконтроль программы**.
4. Введите почту и пароль личного кабинета, ID адаптера котла и ID программы отопления.

ID виден в адресе страницы кабинета: `#equipment/<ID>` или `#program/<ID>`.
Текущая версия требует существующие адаптер котла и программу отопления, доступные этому аккаунту. Подключение аккаунта без этих объектов пока не поддерживается.

Проверена в Home Assistant 2026.9.3 на системе Эктоконтроль 3.2. Совместимость с другими версиями требует проверки.

## HACS

После публикации GitHub-репозитория его можно добавить в HACS как пользовательский репозиторий категории **Integration**. Репозиторий пока не включён в стандартный каталог HACS; автоматическая проверка HACS не выполнялась.

## Доступ и ограничения

Используется внутренний интерфейс `https://my.ectostroy.ru/api/`, а не публичный API ключ. Интерфейс производителя может измениться без предупреждения. Интеграция требует интернет и работающий кабинет.

Пароль хранится в конфигурации Home Assistant. Защищайте конфигурацию и резервные копии. Не публикуйте `.storage`, диагностические выгрузки, токены или реальные ответы кабинета.

Управление выполняется только при действии пользователя или автоматизации. При неопределённом результате команда автоматически не повторяется. Изменение уставок, режимов и выходов влияет на реальное оборудование. Проверяйте назначение сущностей перед использованием в автоматизациях.

Удалённые из кабинета объекты могут оставаться в реестре Home Assistant как недоступные; автоматическая очистка реестра не реализована.

## Разработка

`python scripts/check_package.py` проверяет синтаксис, JSON и отсутствие персональных ID исходной установки. Это статическая проверка, а не тест подключения к реальному кабинету.

Перед релизом проверяйте установку на отдельной системе. Не тестируйте команды на рабочем котле без согласования.
